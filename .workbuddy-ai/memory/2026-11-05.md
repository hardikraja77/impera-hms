# 2026-11-05

## Bug fix: consultations.status ENUM mismatch (SQLSTATE 1265)
- Symptom: `insert into consultations (... status ...) values (... 'pending' ...)` → `SQLSTATE[01000]: Warning: 1265 Data truncated for column 'status'`. Local "worked" but failed in production.
- Root cause: `consultations.status` is `ENUM('in_progress','consulted','completed')` (migration `2024_01_01_000004`), but app inserts/queries `'pending'` (`ReceptionistController` store/storeVisit, `DoctorController`). `patients.status` was extended to include `pending` (`2026_08_20`) but `consultations.status` was not.
- Why prod fails, local ok: `config/database.php` sets `'strict' => true`; lenient local MySQL silently truncates to `''`, strict prod throws.
- Fix: new migration `2026_11_05_000001_add_pending_to_consultations_status.php` alters enum to include `pending` and repairs corrupted `''` rows → `pending`. Apply with `php artisan migrate` on both envs.
- Lesson: when extending a status enum on one table, check all related tables/code that share the same logical status vocabulary.
